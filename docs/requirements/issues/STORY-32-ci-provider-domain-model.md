# STORY-32 CI 도구 공통 도메인/API 모델 확장

## 유형

- Story

## 구현 상태

- 신규 요구사항

## 우선순위

- 높음

## 요약

시스템은 Bamboo와 Jenkins를 함께 지원하기 위해 `CI 도구 유형`을 포함한 공통 도메인 모델과 API 구조를 정의해야 한다.

## 배경

- 현재 데이터 모델과 API는 Bamboo 중심 표현이 많다.
- Jenkins 등록과 운영 현황 조회를 추가하려면 공통 필드와 도구별 전용 필드를 함께 다룰 수 있는 구조가 필요하다.

## 설명

이 Story는 다중 CI 도구 지원의 기반이 되는 백엔드 모델과 API 표현을 정의한다. 프로젝트, 저장소, 빌드 단위, 운영 현황 같은 공통 개념은 재사용하되, `ci_provider` 또는 동등한 식별자를 기준으로 Bamboo와 Jenkins를 구분해야 한다. 또한 Bamboo의 `plan`과 Jenkins의 `job` 같은 도구별 개념은 공통 조회 모델과 도구별 상세 모델을 함께 제공하는 방식이 필요하다. UI 모드 전환과 Jenkins 등록 기능은 이 모델 정의를 전제로 한다.

## 범위

### 포함

- `CI 도구 유형` 필드 정의
- 프로젝트/빌드 단위 공통 모델 확장
- Bamboo plan과 Jenkins job의 공통 API 표현 정의
- 도구별 운영 현황 응답 구조 초안
- UI 모드 전환과 연결되는 API 계약 정의

### 제외

- 실제 Bamboo/Jenkins API 연동 구현
- 권한 체계 전면 개편

## 수용 기준

- 공통 모델에서 Bamboo와 Jenkins를 구분하는 필드가 정의된다.
- Bamboo plan과 Jenkins job의 공통 조회/API 표현 방식이 정의된다.
- 도구별 전용 필드와 공통 필드의 경계가 정의된다.
- UI 모드 전환과 등록 기능이 사용할 API 계약이 정의된다.

## 오픈 이슈

- 공통 추상어를 `build`, `job`, `plan`, `pipeline` 중 무엇으로 둘지 결정 필요
- 기존 Bamboo 중심 API 경로를 확장할지 신규 버전 경로를 만들지 결정 필요
