## 구현 상태

## 우선순위

- 중간

## 다음 구현 포인트

- JSON 적재용 일회성 도구와 반복 동기화 도구 중 방향 선택
- 적재 검증 리포트 형식 정의

## 요약

기존 `build_info_json/` 기반 빌드 정의를 초기 DB 데이터로 적재하고, 전환 기간 동안 필요한 경우 JSON과 DB 사이의 동기화 경로를 제공해야 한다.

## 배경

현재 저장소에는 이미 생성기 입력으로 사용하는 JSON 파일들이 존재한다. DB 전환은 빈 상태에서 시작할 수 없으므로 초기 적재와 점진적 전환 전략이 필요하다.

## 설명

시스템은 기존 JSON 파일을 읽어 DB에 적재할 수 있어야 한다. 전환 초기에는 운영 안정성을 위해 JSON을 원본으로 DB를 채우는 단방향 적재 또는 JSON과 DB를 병행 검증하는 동기화 경로가 필요할 수 있다. 이 과정에서 어떤 항목이 손실 없이 이전되어야 하는지와 충돌 시 우선 원천이 무엇인지 정의해야 한다.

## 수용 기준

- 기존 JSON 데이터를 DB에 적재하는 초기 경로 요구사항이 정의되어 있다.
- 전환 기간 중 JSON과 DB의 병행 운영 또는 검증 방식이 정의되어 있다.
- 데이터 충돌 또는 누락 발생 시 우선 원천과 처리 방침이 정의되어 있다.
- 적재 결과를 검증할 최소 기준이 정의되어 있다.
