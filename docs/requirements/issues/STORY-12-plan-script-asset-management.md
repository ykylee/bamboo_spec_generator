# STORY-12 플랜 스크립트 자산 분리 및 환경별 커스터마이징 관리

## 유형

- Story

## 요약

플랜 Task 스크립트는 공통 자산과 빌드 환경별 가변 요소를 분리해 저장소의 별도 파일로 관리하고, Specs 생성 시 대상 환경에 맞게 커스터마이징된 최종 스크립트로 반영할 수 있어야 한다.

## 배경

현재 생성기는 Task 실행 로직을 코드 내부 문자열로 직접 구성하는 비중이 높다. 하지만 실제 운영 스크립트는 공통 부분이 많고, OS, 셸, 컴파일러, 작업 경로, 명령 조합에 따라 달라지는 부분도 분명하다. 이 차이를 코드 내부 문자열 조합으로 계속 관리하면 변경, 검토, 재사용, 배포가 어려워진다.

## 설명

시스템은 준비, 빌드, 정적 분석, 후속 작업 등 Task 실행 스크립트를 공통 자산과 환경별 가변 요소로 나눠 관리해야 한다. 공통 자산은 저장소에서 직접 편집 가능한 파일로 관리하고, 생성 시점에는 대상 빌드 정의의 OS, 셸, 컴파일러, 작업 하위 경로, 실행 명령에 맞춰 필요한 값이 치환되거나 조합되어 최종 스크립트로 반영되어야 한다. 스크립트 형태의 Task는 스크립트 언어에 맞는 파일 단위로 관리해야 하며, 최소한 `sh`, `bat`, `py` 파일을 명시적으로 다룰 수 있어야 한다. 이 구조는 공통 스크립트 수정이 여러 플랜 생성 결과에 일관되게 반영되도록 해야 하며, 사람이 diff와 코드리뷰를 수행하기 쉬운 형태여야 한다.

## 수용 기준

- 공통 스크립트 자산을 저장소의 별도 파일로 관리한다고 정의되어 있다.
- 빌드 환경별 차이를 공통 자산과 분리해 표현한다고 정의되어 있다.
- Specs 생성 시 대상 빌드 환경에 맞춰 최종 스크립트가 커스터마이징된다고 정의되어 있다.
- 스크립트 형태의 Task가 언어별 파일 단위로 관리된다고 정의되어 있다.
- 최소한 `sh`, `bat`, `py` 파일 관리 요구사항이 포함되어 있다.
- 스크립트 파일이 사람이 직접 수정하고 검토하기 쉬운 구조여야 한다고 정의되어 있다.
- 공통 스크립트 변경 영향이 여러 플랜 생성 결과에 일관되게 반영되는 구조가 정의되어 있다.
- 관련 생성 로직과 자산 구조를 검증할 자동 테스트 또는 동등 수준의 검증 방법이 정의되어 있다.
