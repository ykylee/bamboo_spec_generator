# STORY-17 생성기의 DB 조회 전환 및 마이그레이션 전략 수립

## 유형

- Story

## 구현 상태

- 미구현

## 우선순위

- 높음

## 다음 구현 포인트

- JSON loader와 DB loader를 공통 내부 모델로 연결할 어댑터 경계 정의
- CLI에서 입력 소스 전환 옵션을 도입할지 결정

## 요약

현재 JSON 파일을 직접 읽는 생성기를 운영 백엔드의 Ninja API 조회 기반 구조로 전환하기 위한 단계별 연동 전략과 마이그레이션 계획을 정의해야 한다.

## 배경

현재 생성기 구현은 파일 시스템의 JSON 입력을 전제로 한다. DB 관리 요구사항이 추가되면 생성기 입력 경로, 검증 흐름, 실패 처리, fallback 전략까지 다시 정리해야 한다.

## 설명

시스템은 생성기가 DB에서 활성 빌드 정의를 조회해 Bamboo Specs 생성에 사용할 수 있도록 전환 방향을 정의해야 한다. 이때 초기 단계에서는 JSON 기반 입력을 완전히 제거하지 못할 수 있으므로, JSON fallback, 병행 검증, 단계별 cut-over 방식 같은 마이그레이션 전략이 필요하다. 또한 DB 조회 실패 시 처리 기준, 입력 검증 위치, 생성 재현성 확보 방식도 함께 정리해야 한다.

## 수용 기준

- 생성기의 DB 조회 기반 전환 방향이 정의되어 있다.
- 전환 초기의 JSON fallback 또는 병행 운영 전략이 정의되어 있다.
- 단계별 cut-over 기준과 리스크가 정리되어 있다.
- 생성 재현성과 입력 검증 책임 위치가 문서화되어 있다.
