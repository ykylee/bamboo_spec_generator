# STORY-26 운영 관리 API 표준화

## 유형

- Story

## 구현 상태

- 부분 구현

## 우선순위

- 높음

## 요약

운영 관리 기능 전반을 UI 종속 기능이 아닌 API 우선 구조로 표준화해야 한다.

## 배경

- 사용자 요청 기능은 모두 API 지원이 전제되어야 외부 연동과 자동화가 가능하다.
- 기존 API는 일부 조회/적재 중심이며 관리 기능 전체를 포괄하는 표준이 아직 없다.

## 설명

프로젝트 등록/수정, 사용자 관리, 빌드 현황 조회, Bamboo 시스템 운영 현황 조회 기능은 일관된 리소스 구조와 인증 경계를 가진 HTTP API로 먼저 정의해야 한다. UI는 이 API를 그대로 사용하는 소비자로 본다. 응답 스키마, 페이징, 필터링, 오류 응답 형식, 인증/권한 적용 위치를 공통 규칙으로 정리해야 한다.

## 범위

### 포함

- 운영 관리 API 리소스 구조 정의
- 공통 응답/오류 형식 정의
- 인증/권한 적용 기준 정의
- 페이지네이션/필터링 규칙 정의

### 제외

- 외부 공개용 개발자 포털
- GraphQL 도입

## 수용 기준

- 신규 운영 기능의 API 우선 원칙이 문서화된다.
- 공통 응답 및 오류 형식 기준이 정의된다.
- 인증/권한 적용 기준이 정의된다.
- 프로젝트, 사용자, 빌드 현황, Bamboo 시스템 현황 기능에 공통 API 설계 규칙을 적용할 수 있다.

## 오픈 이슈

- 내부 운영 API 버저닝을 언제부터 강제할지 결정 필요
