# STORY-13 빌드 정의 DB 스키마 및 저장 모델 정의

## 유형

- Story

## 구현 상태

- 미구현

## 우선순위

- 높음

## 다음 구현 포인트

- 현재 JSON 필드와 DB 엔터티 매핑 표 확정
- 공통 내부 모델과 DB 저장 모델의 경계 확정

## 요약

현재 JSON으로 관리하는 빌드 정의 항목을 DB에서 일관되게 저장할 수 있도록 빌드 정의 중심의 데이터 모델과 저장 범위를 정의해야 한다.

## 배경

생성기의 현재 입력은 파일 기반 JSON 구조다. DB 전환을 진행하려면 어떤 항목이 핵심 빌드 정의인지, 어떤 항목이 하위 설정인지, 어떤 식별자로 연관 관계를 맺는지 먼저 정리해야 한다.

## 설명

시스템은 빌드 식별 정보, 플랜 키, 설명, 저장소 연결, 빌드 명령, 정적 분석 설정, 후속 트리거 설정, 런타임 요구사항 등 현재 JSON 입력에서 사용 중인 핵심 데이터를 DB에 저장할 수 있어야 한다. 이때 빌드 정의 자체와 하위 설정 블록의 경계를 정리하고, 생성기가 읽기 쉬운 구조로 엔터티 및 관계를 정의해야 한다.

## 수용 기준

- 현재 JSON 입력 항목 중 DB 관리 대상 필드가 식별되어 있다.
- 빌드 정의의 핵심 엔터티와 하위 설정 엔터티 경계가 정의되어 있다.
- 빌드 정의 식별자와 연관 관계 기준이 정의되어 있다.
- 생성기가 조회 가능한 수준의 저장 모델 요구사항이 문서화되어 있다.
