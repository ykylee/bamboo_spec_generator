# STORY-21 프로젝트 등록 기능 도입

## 유형

- Story

## 구현 상태

- 부분 구현

## 우선순위

- 높음

## 요약

운영자가 신규 프로젝트를 등록하고, 여러 저장소 및 해당 저장소에 연결된 빌드 플랜과 함께 운영 시스템에 온보딩할 수 있어야 하며, 충분한 정보가 갖춰진 프로젝트는 Specs 생성기와 연동 가능한 상태로 관리할 수 있어야 한다.

## 배경

- 현재 프로젝트 정보는 주로 입력 JSON이나 내부 데이터 적재 흐름에 의존한다.
- 운영 시스템으로 확장하려면 프로젝트를 명시적으로 등록하고 관리할 수 있는 기능이 필요하다.

## 설명

프로젝트 등록 기능은 운영 콘솔의 시작점이다. 운영자는 프로젝트 식별자, 이름, 설명, 대표 저장소, 관련 빌드 플랜 또는 빌드 그룹 정보를 등록할 수 있어야 한다. 등록 시 저장소는 여러 개를 입력할 수 있어야 하며, 각 빌드는 특정 저장소에 연결되는 하위 항목으로 관리할 수 있어야 한다. 저장소별 하위 빌드 입력 구조는 사용자에게 어떤 빌드가 어떤 저장소를 기준으로 생성·운영되는지 분명하게 보여줘야 한다. 등록된 프로젝트는 이후 프로젝트 정보 조회/수정, 빌드 현황 조회, 사용자 접근 제어의 기준이 된다. 또한 생성기에 필요한 저장소, 브랜치, 빌드 명령, 에이전트 요구사항 같은 정보가 충족되면 해당 프로젝트를 Specs 생성 가능 상태로 식별할 수 있어야 한다. 프로젝트 등록은 UI뿐 아니라 API를 통해서도 가능해야 한다.

## 범위

### 포함

- 프로젝트 등록 입력 항목 정의
- 프로젝트-저장소-플랜 연결 정보 저장
- 저장소 다중 등록
- 빌드-저장소 연결 구조
- 저장소 하위의 빌드 입력 구조
- 빌드 입력 최소 필드 정의
- 활성/비활성 상태 관리
- 등록 API
- 생성기 연동을 위한 필수 메타데이터 충족 여부 판정
- Specs 생성 또는 플랜 등록 요청의 출발점 정의

### 제외

- 대량 일괄 등록 UI
- 외부 시스템과의 자동 동기화

## 수용 기준

- 프로젝트 등록에 필요한 최소 필드가 정의된다.
- 프로젝트 등록 시 여러 저장소와 플랜 연결 정보를 함께 저장할 수 있다.
- 각 빌드는 특정 저장소에 연결된다.
- 저장소별로 하위 빌드 항목을 추가할 수 있다.
- 빌드 입력 최소 필드로 `빌드 이름`, `빌드 플랜 키`, `언어`, `컴파일러`가 정의된다.
- 등록된 프로젝트는 활성/비활성 상태를 가진다.
- 등록 기능이 API로도 제공된다.
- 생성기 연동에 필요한 필수 메타데이터 세트를 식별할 수 있다.
- 충분한 정보가 있는 프로젝트를 Specs 생성 가능 상태로 판정할 수 있다.

## 오픈 이슈

- 프로젝트 등록 시 필수 메타데이터의 최소 범위를 어디까지 둘지 결정 필요
- 등록 이후 Bamboo 플랜 등록을 자동 호출할지 수동 승인 단계를 둘지 결정 필요
- 빌드 입력 구조를 저장소 중첩형 API payload로 고정할지, 평면 payload와 UI 계층만 분리할지 결정 필요
