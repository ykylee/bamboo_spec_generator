# STORY-31 Jenkins 프로젝트 및 빌드 잡 등록 기능 도입

## 유형

- Story

## 구현 상태

- 신규 요구사항

## 우선순위

- 높음

## 요약

시스템은 Jenkins 모드에서 Bamboo Specs 등록과 유사한 운영 흐름으로 프로젝트와 빌드 잡을 등록할 수 있어야 한다.

## 배경

- 사용자 요구는 Bamboo뿐 아니라 Jenkins도 같은 시스템 안에서 관리하는 것이다.
- Jenkins를 단순 조회만 지원하면 실제 온보딩과 운영 관리가 분리되어 콘솔 일관성이 떨어진다.

## 설명

Jenkins 모드의 등록 기능은 Bamboo 쪽 프로젝트 등록 흐름과 최대한 유사해야 한다. 사용자는 프로젝트를 만들고 저장소를 연결한 뒤, 해당 프로젝트 아래에 하나 이상의 Jenkins 빌드 잡을 등록할 수 있어야 한다. 등록 항목은 공통 필드와 Jenkins 전용 필드를 함께 담을 수 있어야 하며, 후속 단계에서 Jenkins job 생성 또는 동기화 흐름으로 연결될 수 있도록 충분한 메타데이터를 수집해야 한다.

## 범위

### 포함

- Jenkins 프로젝트 등록
- Jenkins 저장소 연결 정보 등록
- Jenkins 빌드 잡 등록
- Jenkins 등록 필드 최소 세트 정의
- Bamboo 등록 흐름과의 공통 UX 정렬

### 제외

- Jenkins 서버에 실제 job 생성 자동화
- Jenkins pipeline 스크립트 편집기

## 수용 기준

- Jenkins 모드에서 프로젝트를 등록할 수 있다.
- Jenkins 프로젝트 아래에 하나 이상의 빌드 잡을 등록할 수 있다.
- 잡 등록 시 최소한 잡 이름, 잡 식별 경로 또는 키, 저장소 연결 정보, 언어, 컴파일러를 입력할 수 있다.
- Bamboo 등록 흐름과 공통 필드가 일관되게 표현된다.

## 오픈 이슈

- Jenkins 잡 식별자를 `fullName`, `folder/path`, 별도 내부 키 중 무엇으로 표준화할지 결정 필요
- freestyle job과 pipeline job을 같은 등록 모델로 처리할지 결정 필요
