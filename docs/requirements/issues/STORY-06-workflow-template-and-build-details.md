# STORY-06 공통 워크플로우 템플릿 및 빌드 상세 입력 구조 정의

## 유형

- Story

## 요약

모든 Bamboo 플랜이 동일한 워크플로우를 사용하도록 공통 스테이지 템플릿을 정의하고, JSON 입력은 언어 및 컴파일러 환경에 따른 빌드 상세 설정만 담도록 정리한다.

## 배경

플랜마다 스테이지 구조를 따로 정의하면 입력이 복잡해지고 운영 표준화가 어려워진다. 요구사항상 모든 플랜은 동일한 워크플로우를 따라야 하므로, 생성기 내부에 공통 템플릿을 두고 JSON은 변경 가능한 상세 설정만 제공하는 구조가 더 적합하다.

## 설명

공통 워크플로우는 `빌드 준비`, `빌드`, `정적분석`, `후속 작업 트리거` 순서로 고정한다. 정적분석 스테이지는 2개의 병렬 Job으로 구성하며, 첫 번째 Job은 Coverity를 사용하고 두 번째 Job은 커스텀툴을 사용한다. 커스텀툴 Job은 지정된 명령어 셋으로 구성되고 그 안에 `analyze {build command}` 패턴의 명령을 포함해야 한다. JSON 입력은 스테이지 목록을 직접 제공하지 않고, 언어, 컴파일러 또는 빌드 도구, 준비 명령, 빌드 명령, 정적분석 명령, 후속 작업 트리거 설정 등 빌드 상세 정보만 담아야 한다.

## 수용 기준

- 모든 플랜에 공통으로 적용되는 스테이지 순서가 정의되어 있다.
- JSON 입력에서 스테이지 정의가 제거되어 있다.
- JSON은 언어, 컴파일러, 빌드 상세 설정 중심으로 정의되어 있다.
- 공통 워크플로우와 입력 상세 정보 간 매핑 규칙이 문서화되어 있다.
- 정적분석 스테이지가 2개의 병렬 Job으로 정의되어 있다.
- 정적분석 병렬 Job이 각각 Coverity와 커스텀툴로 고정되어 있다.
- 커스텀툴 명령어 셋에 `analyze {build command}` 패턴이 포함된다고 정의되어 있다.
- 후속 작업 트리거가 공통 워크플로우에 포함되어 있다.
