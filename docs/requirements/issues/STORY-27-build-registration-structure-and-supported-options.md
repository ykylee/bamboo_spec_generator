# STORY-27 빌드 등록 구조 및 지원 언어/컴파일러 선택 방식 정의

## 유형

- Story

## 구현 상태

- 요구사항 정의 및 일부 UI 반영

## 우선순위

- 높음

## 요약

프로젝트 등록 화면에서 빌드 항목은 저장소 하위 항목으로 입력할 수 있어야 하며, 빌드 등록 시 `빌드 이름`, `빌드 플랜 키`, `언어`, `컴파일러`를 입력하고 시스템 지원 목록에서 선택할 수 있어야 한다.

## 배경

- 현재 프로젝트 등록은 저장소와 빌드 정보를 함께 다루지만, 사용자 관점에서는 빌드가 어떤 저장소에 속하는지 더 명확히 보여줄 필요가 있다.
- 언어와 컴파일러는 시스템이 실제로 지원하는 범위를 안내해야 입력 품질과 후속 생성 성공률이 올라간다.

## 설명

프로젝트 등록 UI는 저장소를 상위 항목으로 두고, 각 저장소 아래에 해당 저장소와 연결될 빌드 항목을 입력하는 구조를 제공해야 한다. 빌드 입력 필드는 최소한 `빌드 이름`, `빌드 플랜 키`, `언어`, `컴파일러`를 포함해야 한다. `언어`와 `컴파일러`는 자유 입력만 두기보다 현재 시스템이 지원하는 목록을 선택형으로 제안해야 하며, 필요하면 추가 설명이나 기본값도 제공할 수 있어야 한다. 이 구조는 운영 UI뿐 아니라 API와 내부 모델에서도 일관되게 표현될 수 있어야 한다. 또한 지원 목록은 사용자가 입력 가능한 값의 품질을 높이는 역할을 하므로, 단순 표시가 아니라 실제 검증 기준과 연결될 수 있어야 한다.

## 범위

### 포함

- 저장소 하위 빌드 입력 구조
- 빌드 입력 최소 필드 정의
- 지원 언어 목록 정의
- 지원 컴파일러 목록 정의
- UI 선택형 입력 방식 정의
- 선택값의 검증 및 호환성 정책 정의

### 제외

- 실제 Specs 생성 연동
- Bamboo 서버 등록 자동화

## 수용 기준

- 빌드 입력이 저장소 하위 항목 구조로 정의된다.
- 빌드 입력 최소 필드로 `빌드 이름`, `빌드 플랜 키`, `언어`, `컴파일러`가 정의된다.
- 언어와 컴파일러에 대해 시스템 지원 목록이 정의된다.
- UI에서 목록 선택 방식이 정의된다.
- 저장소-빌드 연결 관계가 API와 내부 모델에서 일관되게 표현될 수 있다.
- 지원 목록과 실제 입력 검증 규칙의 연계 방안이 정의된다.

## 오픈 이슈

- 언어와 컴파일러를 선택형 전용으로 제한할지, 자유 입력을 함께 허용할지 결정 필요
- 지원 목록의 기준 데이터를 정적 상수로 둘지 DB/설정으로 뺄지 결정 필요
- 지원 목록 변경 시 기존 등록 빌드의 호환성을 어떻게 유지할지 결정 필요
