# STORY-04 단일 Specs 저장소 구조 및 등록 방식 설계

## 유형

- Story

## 요약

여러 타겟 빌드의 생성 결과를 하나의 Bamboo Specs 저장소 안에 구성하고, Bamboo가 해당 저장소만 스캔해 전체 플랜을 반영할 수 있는 구조를 설계한다.

## 배경

여러 빌드를 한 번에 처리하더라도 실제 운영에서는 하나의 Specs 저장소만 관리하면서 각 플랜을 식별할 수 있어야 한다. 저장소 구조와 파일 배치 규칙이 불명확하면 생성물 관리와 Bamboo 반영 절차가 어려워진다.

## 설명

생성된 Bamboo Specs Java 코드가 하나의 Bamboo Specs 프로젝트 안에 배치되도록 출력 구조를 정의한다. 필요하면 연도, 빌드 식별자, 패키지 구조, 클래스명 규칙을 포함하고, Bamboo가 단일 저장소 스캔으로 전체 플랜을 반영할 수 있도록 해야 한다. 또한 저장소 연결 모드가 `create_if_missing`인 경우 후속 등록이 필요한 지점을 추적할 수 있는 메타데이터 배치 규칙도 함께 정의해야 한다.

## 수용 기준

- 단일 Bamboo Specs 저장소 구조가 정의되어 있다.
- 연도와 빌드 식별자를 반영한 클래스 또는 패키지 배치 규칙이 정의되어 있다.
- 여러 빌드를 한 번에 생성하더라도 결과를 플랜별로 식별할 수 있다.
- Bamboo가 하나의 Specs 저장소를 스캔해 전체 플랜을 반영할 수 있는 구조가 문서화되어 있다.
- 필요 시 저장소 연결 보조 메타데이터를 어디에 둘지 규칙이 정의되어 있다.

## 오픈 이슈

- 단일 저장소 커밋이 여러 플랜에 동시에 영향을 줄 때 운영 정책을 어떻게 둘지 결정 필요
- 산출물 저장 경로를 생성기 저장소 내부에 둘지 별도 Specs 저장소로 분리할지 결정 필요
- `create_if_missing` 관련 보조 메타데이터를 Java 코드 내부에 둘지 별도 산출물로 둘지 결정 필요
