## 요약

각 빌드 플랜의 실행 결과를 플랜 단위로 정리하고, 빌드 실행별 주요 메타데이터를 DB에 저장하고 조회할 수 있는 모델을 정의해야 한다.

## 배경

운영 중에는 어떤 빌드 플랜이 언제 성공했고 언제 실패했는지, 최근 결과가 어떤지, 특정 버전 검증이 통과했는지 추적할 필요가 있다. 또한 빌드 번호, 커밋 해시, 정적 분석 결과 같은 실행 메타데이터도 함께 남아야 한다. 이는 정적인 빌드 정의와 별도 관리되어야 하는 대표적인 운영 데이터다.

## 설명

시스템은 빌드 실행 단위로 실행 시각, 대상 빌드 플랜, 빌드 번호, 커밋 해시, 성공 여부, 결과 상태, 정적 분석 결과, 요약 메시지, 관련 버전 정보, 필요 시 외부 로그 참조를 저장할 수 있어야 한다. 또한 빌드 실패 시 실패한 스테이지와 잡을 저장할 수 있어야 하며, 가능하면 태스크 단위까지 식별할 수 있어야 한다. 저장 항목은 초기 정의 이후에도 확장 가능해야 한다. 또한 최근 결과 조회, 상태 이력 조회, 빌드 정의와의 연결 추적이 가능해야 한다. 결과 상태는 최소한 성공, 실패, 취소 또는 동등 수준의 종료 상태를 지원해야 한다.

## 수용 기준

- 빌드 실행 결과 엔터티와 빌드 플랜 간 관계가 정의되어 있다.
- 최소 저장 항목으로 실행 시각, 대상 빌드 플랜, 빌드 번호, 커밋 해시, 성공 여부, 상태, 정적 분석 결과, 결과 요약이 포함되어 있다.
- 빌드 실패 시 최소한 실패 스테이지와 실패 잡을 기록할 수 있어야 한다.
- 가능하면 실패 태스크까지 식별해 기록할 수 있어야 한다.
- 최근 결과 조회 및 이력 추적이 가능한 구조 요구사항이 정의되어 있다.
- 결과 저장 항목이 향후 확장 가능해야 한다는 요구사항이 포함되어 있다.
- 외부 로그 또는 상세 결과 참조를 연결할 수 있는 방향이 포함되어 있다.
