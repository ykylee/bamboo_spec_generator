# CRS: 빌드 작업 하위 경로 지정 지원

## 문서 메타데이터

- 문서 일자: 2026-03-17
- 문서 유형: CRS
- 상태: 초안
- 대상 프로젝트: `bamboo_spec_generator`
- Jira 전환 대상: Story 초안

## 요약

빌드가 항상 저장소 루트에서 수행되는 것은 아니므로, 입력 JSON에서 하위 작업 경로를 지정하고 생성된 플랜이 해당 경로를 기준으로 빌드와 분석을 수행할 수 있어야 한다.

## 배경

- 실제 저장소는 모노레포 또는 다중 모듈 구조일 수 있어, 솔루션 파일이나 빌드 스크립트가 저장소 루트가 아닌 하위 디렉터리에 위치하는 경우가 많다.
- 빌드 위치가 루트로 고정되면 동일 저장소 내 여러 애플리케이션을 개별 플랜으로 다루기 어렵다.
- MSBuild의 `Directory.Build.targets` 같은 파일도 실제 빌드 작업 디렉터리를 기준으로 생성되어야 효과가 있으므로, 작업 경로 모델이 필요하다.

## 문제

현재 입력 모델은 빌드 실행 위치를 별도로 표현하지 않아 모든 준비, 빌드, 정적 분석 명령이 저장소 루트를 기준으로 실행된다고 가정한다. 이 경우 하위 디렉터리 기반 프로젝트는 명령 경로가 틀어지거나, 우회용 파일이 잘못된 위치에 생성될 수 있다.

## 범위

### 포함 범위

- 입력 JSON에 빌드 작업 하위 경로를 표현하는 필드 정의
- 빌드 작업 하위 경로의 기본값과 검증 규칙 정의
- 준비, 빌드, 정적 분석, 후속 스크립트 실행 시 적용할 작업 디렉터리 규칙 정의
- `Directory.Build.targets` 같은 보조 파일 생성 위치와 작업 경로의 관계 정의

### 제외 범위

- 복수 작업 경로를 한 빌드 정의에서 동시에 지원하는 기능
- 경로 패턴 확장이나 글롭 기반 다중 매칭
- 저장소 외부 경로를 참조하는 기능

## 요구사항

### 기능 요구사항

- 시스템은 입력 JSON에서 빌드 작업 하위 경로를 읽을 수 있어야 한다.
- 시스템은 작업 하위 경로가 생략되면 저장소 루트를 기본 작업 위치로 사용해야 한다.
- 시스템은 준비, 빌드, 정적 분석 단계에서 해당 하위 경로를 작업 디렉터리로 적용해야 한다.
- 시스템은 `Directory.Build.targets` 같은 보조 파일을 실제 빌드 작업 경로에 생성해야 한다.
- 시스템은 작업 하위 경로가 저장소 내부 상대경로인지 검증해야 한다.

### 비기능 요구사항

- 경로 해석 방식은 Windows와 Linux에서 모두 일관되어야 한다.
- 경로 지정이 없는 기존 JSON도 기본값으로 계속 동작할 수 있어야 한다.
- 생성 로직은 경로 처리 때문에 명령 문자열을 과도하게 복잡하게 만들지 않아야 한다.

## 수용 기준

- 입력 JSON 모델에 작업 하위 경로 필드가 정의되어 있다.
- 필드가 없을 때 저장소 루트를 기본 작업 위치로 사용한다고 정의되어 있다.
- 준비, 빌드, 정적 분석 단계가 동일한 작업 하위 경로를 기준으로 실행된다고 정의되어 있다.
- `Directory.Build.targets` 생성 위치가 작업 하위 경로와 일치한다고 정의되어 있다.
- 상대경로 검증 규칙과 오류 처리 방식이 정의되어 있다.

## 제약/가정

- 작업 하위 경로는 저장소 기준 상대경로로만 허용한다고 가정한다.
- 초기 범위에서는 단일 경로만 지원하고, 단계별 개별 작업 경로 분리는 후속 범위로 둔다.
- 하위 경로가 지정되면 관련 스크립트와 보조 파일은 모두 해당 경로를 기준으로 동작해야 한다.

## 오픈 이슈

- 필드 이름을 `subPath`, `workingSubPath`, `workDir` 중 무엇으로 확정할지 결정이 필요하다.
- 작업 하위 경로를 저장소 블록이 아닌 빌드 블록 아래에 둘지 최종 결정이 필요하다.
- 정적 분석 도구가 자체적으로 다른 작업 디렉터리를 요구하는 경우 예외 모델이 필요한지 검토가 필요하다.
