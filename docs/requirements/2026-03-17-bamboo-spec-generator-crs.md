# CRS: Bamboo Specs 기반 Bamboo 플랜 자동 구성

## 문서 메타데이터

- 문서 일자: 2026-03-17
- 문서 유형: CRS
- 상태: 초안
- 대상 프로젝트: `bamboo_spec_generator`
- Jira 전환 대상: Requirement / Epic / Story 초안

## 요약

이 프로젝트는 Bamboo Specs를 활용해 Bamboo 플랜 구성을 자동화하는 것을 목표로 한다. 사용자는 연도별로 관리되는 하나 이상의 JSON 파일에 타겟 빌드 정보를 저장하고, 애플리케이션은 이를 읽어 각 빌드에 대응하는 Bamboo Specs Java 코드를 생성해야 한다. 생성 결과는 하나의 Bamboo Specs 저장소 안에서 여러 타겟 빌드를 함께 관리할 수 있어야 하며, Bamboo는 해당 저장소만 확인해 전체 플랜 변경을 일괄 반영할 수 있어야 한다.

## 배경

- Bamboo 플랜을 수동으로 반복 구성하는 작업은 시간 소모와 설정 편차를 유발한다.
- 빌드 정의를 JSON으로 정형화하면 재사용성과 변경 관리가 쉬워진다.
- Bamboo Specs Java 코드를 자동 생성하면 수작업 작성 비용을 줄이고 표준화를 강화할 수 있다.
- Atlassian이 기본 제공하는 Bamboo Specs Base 코드를 저장소에 미리 보관하면 생성 로직 구현과 유지보수에 유리하다.

## 문제

현재 Bamboo 플랜 구성이 수작업 중심이거나 반복 작업에 의존할 가능성이 높다. 이 경우 설정 누락, 플랜 간 구성 편차, 유지보수 비용 증가가 발생할 수 있다. Bamboo Specs Java 코드를 직접 작성하는 방식 역시 다수의 타겟 빌드와 연도별 운영 체계를 관리하기에 비효율적일 수 있다.

## 범위

### 포함 범위

- JSON 형식의 타겟 빌드 정보 저장
- 여러 개의 타겟 빌드 정보 관리
- 타겟 빌드 정보를 연도별로 관리
- 애플리케이션 실행 시 하나 이상의 JSON 입력 파싱
- 입력된 빌드 정보 각각에 기반한 Bamboo Specs Java 코드 생성
- 여러 타겟 빌드를 하나의 Bamboo Specs 저장소에서 함께 관리 가능한 형태로 처리
- Bamboo Specs Java 생성 시 활용할 Atlassian 기본 Base 코드의 사전 확보 및 저장소 내 보관

### 제외 범위

- 실제 Bamboo 서버에 플랜을 즉시 배포하거나 반영하는 기능
- Bamboo 외 다른 CI/CD 도구용 설정 생성
- JSON 입력을 편집하기 위한 별도 GUI 제공

## 요구사항

### 기능 요구사항

- 시스템은 JSON 형태의 타겟 빌드 정보를 입력으로 받아야 한다.
- 시스템은 하나 이상의 JSON 파일을 입력으로 처리할 수 있어야 한다.
- 시스템은 연도별로 분리되거나 관리되는 타겟 빌드 정보를 다룰 수 있어야 한다.
- 시스템은 애플리케이션 실행 시 지정된 여러 JSON 파일을 읽을 수 있어야 한다.
- 시스템은 각 JSON 입력값을 기반으로 Bamboo Specs Java 코드를 생성해야 한다.
- 생성된 코드는 Bamboo 플랜 구성이 가능하도록 필요한 구조를 포함해야 한다.
- 시스템은 여러 타겟 빌드를 하나의 Bamboo Specs 프로젝트 안에서 함께 생성하고 관리할 수 있어야 한다.
- 시스템은 Atlassian 기본 Bamboo Specs Base 코드를 재사용 가능한 형태로 저장소 내에 보관할 수 있어야 한다.
- 코드 생성 로직은 Base 코드를 활용하는 방향으로 구성되어야 한다.

### 비기능 요구사항

- 입력 포맷은 사람이 관리할 수 있을 정도로 단순하고 명확해야 한다.
- 생성 결과는 반복 실행 시 동일 입력에 대해 일관된 출력을 제공해야 한다.
- 생성 구조는 추후 빌드 유형 확장에 대응할 수 있어야 한다.
- 다수의 빌드 정의와 연도별 분류를 관리할 수 있도록 저장 구조가 명확해야 한다.
- 저장소에 보관하는 Base 코드는 재현 가능하고 관리 가능한 방식으로 유지되어야 한다.

## 입력 및 출력

### 입력

- 타겟 빌드 정보를 담은 하나 이상의 JSON 파일
- 연도별 분류 기준에 따라 관리되는 JSON 파일 집합
- 향후 필요 시 생성 옵션 또는 출력 경로 등의 실행 파라미터

### 출력

- Bamboo 플랜 구성을 위한 Bamboo Specs Java 소스 코드
- 여러 타겟 빌드를 포함하는 단일 Bamboo Specs 프로젝트 산출물
- 필요 시 Base 코드와 생성 코드가 결합되거나 참조되는 저장소 구조

## 수용 기준

- 사용자는 하나 이상의 JSON 파일을 입력으로 지정할 수 있다.
- 시스템은 여러 JSON 파일을 읽어 빌드 정의별로 처리할 수 있다.
- 시스템은 연도별로 관리되는 빌드 정의를 구분할 수 있다.
- 시스템은 각 빌드 정의에 대해 Bamboo Specs Java 코드를 생성할 수 있다.
- 생성 결과는 하나의 Bamboo Specs 저장소 안에서 여러 플랜을 함께 관리할 수 있는 구조다.
- Atlassian Base 코드를 재사용할 수 있도록 저장소 내 관리 위치와 활용 방식이 정의된다.

## 초기 설계 메모

- 입력 모델: 빌드 정보를 표현하는 JSON 스키마 또는 이에 준하는 내부 데이터 구조 정의
- 저장 구조: 연도별 디렉터리 또는 연도 메타데이터를 이용해 다수의 JSON 빌드 정의를 관리하는 구조 설계
- 처리 흐름:
  1. 여러 JSON 파일 탐색 또는 로드
  2. 입력 검증 및 내부 모델 변환
  3. 연도 및 빌드별 구분 정보 정리
  4. Bamboo 플랜 구성 요소 매핑
  5. Bamboo Specs Java 코드 생성
  6. 단일 Bamboo Specs 프로젝트 구조에 결과 반영
- Base 코드 전략:
  - Atlassian 기본 제공 Bamboo Specs Base 코드를 사전에 확보해 저장소 내 별도 위치에 보관
  - 생성 로직은 해당 Base 코드의 구조를 최대한 재사용하도록 설계

## 제약 및 가정

- Bamboo Specs Java 생성에 필요한 Atlassian Base 코드는 저장소에 포함 가능해야 한다.
- Base 코드의 라이선스, 배포 가능 범위, 버전 관리 방식은 별도 확인이 필요하다.
- JSON 포맷의 상세 스키마는 아직 정의되지 않았다.
- 연도별 관리 방식이 디렉터리 기반인지 메타데이터 기반인지 아직 정해지지 않았다.
- 생성 대상 Java 코드의 패키지 구조, 클래스명 규칙, 출력 디렉터리 구조는 후속 설계가 필요하다.
- 단일 Specs 저장소 변경이 여러 플랜에 동시에 영향을 줄 수 있다는 운영상 고려가 필요하다.

## 오픈 이슈

- JSON 스키마에 어떤 빌드 요소를 포함할지 정의 필요
- 여러 JSON 파일을 어떤 규칙으로 탐색하고 로드할지 정의 필요
- 연도별 관리 구조를 디렉터리 규칙으로 강제할지 결정 필요
- 생성 대상 Bamboo 플랜의 최소 구성 요소 범위 정의 필요
- Base 코드를 어떤 경로와 방식으로 저장소에 관리할지 결정 필요
- 생성 코드가 독립 실행형 프로젝트인지, 일부 코드만 생성하는 방식인지 결정 필요
- 여러 빌드를 단일 Specs 저장소에 어떻게 배치할지 결정 필요
- 최종적으로 Bamboo 반영까지 자동화할지 범위 확정 필요
