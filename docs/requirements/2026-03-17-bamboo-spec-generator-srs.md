# SRS: Bamboo Specs 기반 Bamboo 플랜 자동 구성

## 요약

본 시스템은 연도별로 관리되는 하나 이상의 JSON 빌드 정의를 읽고, 각 정의에 대응하는 Bamboo Specs Java 코드를 생성하는 로컬 실행형 생성기다. 생성 결과는 하나의 Bamboo Specs 저장소 안에서 여러 플랜을 함께 관리할 수 있어야 하며, Bamboo는 해당 저장소를 스캔해 전체 플랜 변경을 반영할 수 있어야 한다.

## 배경

- Bamboo 플랜 수작업 구성은 반복 비용과 구성 편차를 유발한다.
- JSON 기반 선언형 입력은 빌드 정의 표준화와 변경 관리에 유리하다.
- Bamboo Specs Java 생성 자동화는 플랜 생성 속도와 일관성을 높인다.
- Base 코드 재사용은 생성 코드 구조를 단순화하고 유지보수성을 높일 수 있다.

## 목표

- 여러 JSON 입력으로부터 Bamboo Specs Java 코드를 자동 생성한다.
- 연도별로 관리되는 다수의 빌드 정의를 일관된 구조로 처리한다.
- 생성 결과를 하나의 Bamboo Specs 프로젝트 안에서 관리 가능한 구조로 만든다.
- Base 코드를 재사용 가능한 방식으로 저장소에 통합한다.

## 비목표

- Bamboo 서버에 자동 배포하거나 즉시 반영하지 않는다.
- JSON 편집용 UI는 제공하지 않는다.
- Bamboo 외 다른 CI/CD 도구용 코드 생성은 지원하지 않는다.

## 사용자 및 사용 시나리오

### 사용자

- 빌드 엔지니어
- DevOps 담당자
- Bamboo 플랜을 운영하는 개발자

### 주요 사용 시나리오

1. 사용자가 연도별 디렉터리 또는 지정된 위치에 JSON 빌드 정의 파일을 배치한다.
2. 사용자가 생성기 앱을 실행하면서 입력 파일 또는 입력 루트를 지정한다.
3. 시스템이 여러 JSON 파일을 읽고 각 빌드 정의를 검증한다.
4. 시스템이 빌드 정의를 내부 모델로 변환하고 Bamboo Specs Java 코드로 생성한다.
5. 시스템이 여러 빌드 정의를 포함한 단일 Bamboo Specs 프로젝트 결과물을 출력한다.

## 기능 요구사항

### FR-01 입력 파일 처리

- 시스템은 하나 이상의 JSON 파일을 입력으로 받을 수 있어야 한다.
- 시스템은 파일 목록 또는 디렉터리 기준 입력을 처리할 수 있어야 한다.
- 시스템은 JSON 파싱 실패 시 대상 파일과 오류 원인을 식별 가능하게 보고해야 한다.

### FR-02 연도별 관리 구조 지원

- 시스템은 빌드 정의를 연도별로 구분할 수 있어야 한다.
- 연도 정보는 입력 디렉터리 구조를 기준으로 해석해야 한다.
- 동일 실행 내 여러 연도의 빌드 정의를 함께 처리할 수 있어야 한다.

### FR-03 빌드 정의 검증

- 시스템은 필수 필드 존재 여부를 검증해야 한다.
- 시스템은 중복 식별자, 누락 필드, 형식 오류를 검출해야 한다.
- 검증 실패 시 전체 중단 여부 또는 부분 처리 여부를 정책으로 정의할 수 있어야 한다.

### FR-04 내부 모델 변환

- 시스템은 JSON 빌드 정의를 Bamboo 플랜 생성에 필요한 내부 모델로 변환해야 한다.
- 내부 모델은 연도, 빌드 식별자, 플랜 식별 정보, 공통 워크플로우 템플릿, 언어 및 컴파일러별 빌드 상세 정보, OS 및 추가 capability 요구사항을 표현할 수 있어야 한다.

### FR-05 Bamboo Specs Java 코드 생성

- 시스템은 내부 모델을 기반으로 Bamboo Specs Java 소스 코드를 생성해야 한다.
- 생성 결과는 Bamboo 플랜 구성을 위한 기본 구조를 포함해야 한다.
- 동일 입력에 대해 반복 실행 시 동일한 결과를 생성해야 한다.
- 모든 생성 플랜은 동일한 스테이지 워크플로우를 따라야 한다.
- 공통 워크플로우의 스테이지는 `빌드 준비`, `빌드`, `정적분석`, `후속 작업 트리거`를 포함해야 한다.
- `정적분석` 스테이지는 2개의 병렬 Job을 포함해야 한다.
- 정적분석 Job 1은 Coverity 실행으로 고정해야 한다.
- 정적분석 Job 2는 커스텀툴 실행으로 고정해야 한다.
- 커스텀툴 Job은 명령어 셋 안에 `analyze {build command}` 패턴의 명령을 포함해야 한다.
- 플랜 간 차이는 언어, 컴파일러 환경, 실제 빌드 명령 등 빌드 상세 설정으로만 표현되어야 한다.
- 스크립트 기반 Task는 가능하면 Windows와 Linux에서 모두 호환될 수 있도록 Python 스크립트 호출 방식을 우선해야 한다.

### FR-06 단일 Specs 프로젝트 구조화

- 시스템은 여러 빌드 정의를 하나의 Bamboo Specs 프로젝트 안에서 함께 생성해야 한다.
- 시스템은 프로젝트 내부에서 빌드 식별이 가능하도록 클래스, 파일 또는 패키지 단위로 구조화해야 한다.
- 연도별 구분이 필요한 경우 입력 관리 기준과 산출물 내부 구조에 반영되어야 한다.

### FR-07 Job Requirement 생성

- 빌드가 포함된 Job은 Bamboo requirement를 가져야 한다.
- requirement는 최소한 OS capability와 compiler capability를 포함해야 한다.
- 프로젝트 특성에 따른 추가 capability를 함께 지정할 수 있어야 한다.
- 현재 지원 compiler capability는 `vs2013`, `vs2015`, `vs2017`, `vs2019`, `vs2022`, `vs2026`, `node.js`, `python`, `maven`, `keil`, `cmake`다.
- 추가 capability 예시는 `cuda12.1`, `nuget`이다.

### FR-08 Base 코드 재사용

- 시스템은 Atlassian Bamboo Specs Base 코드를 참조 또는 포함할 수 있어야 한다.
- Base 코드의 저장 위치와 버전 기준이 정의되어야 한다.
- 생성 로직은 Base 코드와의 결합 지점을 일관되게 유지해야 한다.
- Bamboo가 하나의 Specs 저장소를 스캔해 다수의 플랜을 반영할 수 있는 구조를 지원해야 한다.

### FR-09 실행 결과 보고

- 시스템은 처리한 파일 수, 성공 수, 실패 수를 요약해 출력할 수 있어야 한다.
- 시스템은 생성된 산출물 경로를 사용자에게 제공할 수 있어야 한다.

## 비기능 요구사항

### NFR-01 사용성

- 입력 구조는 사람이 이해하고 관리하기 쉬워야 한다.
- 오류 메시지는 파일명과 원인을 포함해 추적 가능해야 한다.

### NFR-02 일관성

- 동일한 입력과 동일한 Base 코드 버전에서는 동일한 산출물을 생성해야 한다.

### NFR-03 확장성

- 향후 빌드 유형, 단계, 잡, 트리거 등 Bamboo 구성 요소 확장에 대응 가능해야 한다.

### NFR-04 유지보수성

- 입력 파싱, 검증, 내부 모델, 코드 생성, 출력 저장 로직은 분리되어야 한다.
- Base 코드 관리 정책은 문서화되어야 한다.

### NFR-05 추적성

- 요구사항은 이슈 단위와 연결 가능해야 하며 구현 범위를 명확히 추적할 수 있어야 한다.

## 데이터 요구사항

### 입력 데이터 개체

- `buildId`: 빌드 정의 식별자
- `planKey`: Bamboo 플랜 식별 키
- `name`: 플랜 또는 빌드 이름
- `language`: 빌드 대상 언어
- `compiler`: 컴파일러 또는 빌드 도구 식별자
- `build`: 빌드 상세 설정

### 입력 데이터 규칙

- `buildId`와 `planKey`는 동일 범위 내에서 유일해야 한다.
- 연도 정보는 JSON 내부 필드가 아니라 입력 디렉터리 경로에서 결정한다.
- 스테이지 구조는 JSON에서 직접 정의하지 않고 생성기 내부 공통 워크플로우 템플릿으로 고정한다.
- JSON은 언어, 컴파일러 환경, 빌드 명령 등 변경 가능한 빌드 상세 정보만 표현한다.
- JSON은 Coverity 실행 정보와 커스텀툴 명령어 셋을 표현할 수 있어야 한다.
- 최소 실행 가능한 플랜 구성을 위한 필수 필드는 별도 스키마 문서에서 확정해야 한다.

## 시스템 인터페이스

### 입력 인터페이스

- CLI 또는 메인 애플리케이션 인자 기반 실행을 가정한다.
- 입력 파일 경로, 입력 디렉터리, 출력 경로를 전달할 수 있어야 한다.

### 출력 인터페이스

- 다수의 플랜 정의를 포함하는 Bamboo Specs Java 프로젝트
- 처리 결과 요약 로그

## 수용 기준

- 사용자는 하나 이상의 JSON 파일 또는 입력 디렉터리를 지정할 수 있다.

- 시스템은 유효한 입력에 대해 Bamboo Specs Java 코드를 생성할 수 있다.
- 시스템은 단일 Bamboo Specs 저장소 안에서 여러 플랜을 식별 가능하게 생성할 수 있다.
- 시스템은 Base 코드 활용 위치와 방식이 정의된 구조를 가진다.
- 시스템은 실패한 입력에 대한 오류 정보를 식별 가능하게 제공한다.
