# UI 테스트 케이스 세트

## 문서 메타데이터

- 문서 일자: 2026-03-19
- 문서 유형: Manual UI Test Case Set
- 대상 범위: 프로젝트 목록, 프로젝트 등록, 프로젝트 상세, 프로젝트 수정
- 관련 요구사항: [../requirements/SRS.md](../requirements/SRS.md)
- 관련 스토리: [../requirements/issues/STORY-21-project-registration.md](../requirements/issues/STORY-21-project-registration.md), [../requirements/issues/STORY-22-project-read-update.md](../requirements/issues/STORY-22-project-read-update.md)
- 관련 설계: [../designs/detailed_designs/project_registration_and_generation_readiness.md](../designs/detailed_designs/project_registration_and_generation_readiness.md)

## 요약

본 TC 세트는 현재 구현된 조회/등록/수정 UI를 기준으로 작성했다. 요구사항 문서의 장기 목표 전체를 검증하는 세트가 아니라, 2026-03-19 시점 구현 범위 안에서 운영자가 화면으로 확인해야 할 핵심 시나리오를 정리한 것이다.

## 범위

### 포함

- 프로젝트 목록 화면 KPI, 검색, 상태 필터, 페이지네이션
- 메인 화면 등록 패널의 접힘/펼침 및 입력 후보 제안
- 프로젝트 등록 성공/실패 시나리오
- 프로젝트 상세 화면의 준비도, 저장소, 빌드 정보 표시
- 프로젝트 수정 성공/실패 시나리오

### 제외

- API 단독 검증
- 사용자 권한/인증
- 실제 Specs 생성 실행
- Bamboo 연동, 실행 이력 적재, 배포/릴리스 관리
- 브라우저별 스타일 차이, 반응형 세부 레이아웃

## 테스트 데이터 준비 가이드

- 프로젝트 12건 이상을 준비해 페이지네이션을 검증한다.
- 아래 유형이 최소 1건씩 포함되도록 준비한다.
- 생성 준비 완료 프로젝트
- 대표 저장소 미지정 또는 메타데이터 불일치 프로젝트
- 활성 정의 없는 빌드를 가진 프로젝트
- Coverity 정보 일부가 비어 있는 프로젝트
- 최신 빌드 실패 이력이 있는 프로젝트

## 현재 구현 기준 메모

- 요구사항 문서에 언급된 프로젝트 이름, 설명, 활성/비활성 상태 필드는 현재 UI/서비스에 구현되어 있지 않다. 본 TC 세트에서는 제외했다.
- 저장소-빌드 관계는 스토리 문서의 "저장소 하위 빌드 구조"보다 현재 구현상 "평면 빌드 목록 + 저장소 slug 연결" 방식에 맞춰 검증한다.
- 수정 시 수정자 기록은 아직 구현되지 않았고, 수정 시각 노출만 현재 확인 가능하다.
- 최근 실패 빌드 패널은 실행 이력 데이터가 있는 경우에만 검증 가능하다.
